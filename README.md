# Food-Tracker
Project "SnackTracker" completed during the coursework for "CSCI 3308: Software Development Methods and Tools" at the University of Colorado, Boulder.


#### Application Description:

Snacker will be a site that manages an inventory of snacks that will
be held for each ‘group.’ These inventories will be stored in a SQL database and managed
through a frontend HTML website that allows users to directly interact with values of there snack
‘inventory’ this can interact with an automated email or payment system that allows users to
charge other members in their ‘group’ for the cost of certain items.

#### Vision Statement:

Snacker will be a site that tracks an inventory of snacks held by a living community and allows
users to add snacks that they have purchased as well as degrees to which they have consumed
snacks that roommates may have purchased in order to allow for an easier time budgeting and
allocating costs of snack in the group

#### Project Feautures:

- Profile Feature: Users will be able to customize their profiles to their preferences.
For example, a user could change their default background color to blue, and
every time they login, the background color of the site will be blue.
- Trade snack feature: Users will be able to trade snacks. Essentially, a user can
request a trade from a friend, and their friend can accept or decline the trade.
- Household Feature: Users will be able to form groups with other users called
households. This will make it easier to track what a user owes. For example, a
user can form a household with their roommates and make payments to their
roommates within the household.- Request/Make Payment: Users can also request/make payments to other users
directly. This could link to third party apps like PayPal, Venmo, etc.
- Log-In: Users can log into their accounts and use the website with their
previously set profile preferences. This feature will also allow users to create a
new account if they are new to the site.
- Stats Page: This page will display statistics that show how much a user is due to
pay or be paid based on the amount of requests they have sent or been sent. This
should help users to moderate how much they are spending
